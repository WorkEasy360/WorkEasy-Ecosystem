# Phase 12 — Step 1 audit: gap list (before any change)

**Date:** 2026-09-30. **Method:** four parallel read-only audits of the actual repository (security; async/ops/observability; migrations/RLS/SSRF/frontend; product-side OIDC capability), each finding then **re-verified by hand** before it was acted on — by reading the cited code or, where possible, by a live check (for example G-02 below was confirmed by connecting through PgBouncer and reading `SHOW statement_timeout`). Phase reports were not taken as evidence.

Severity: **P0** unsafe to go live / data loss or security failure; **P1** go-live blocker; **P2** must be fixed or accepted with a documented control before or soon after go-live; **P3** hygiene.

"Action" is what Phase 12 did about it. The final state of every row is in [phase-12-status.md](phase-12-status.md).

Every final-audit finding was re-verified by hand against the code before it was acted on.

| ID | Sev | Gap (verified) | Action |

| G-24 | P1 | **Product entitlement verification ignored the organization's own lifecycle.** A staff-suspended organization is read-only on the platform (R-10), but `/integrations/entitlements/verify` answered `write_allowed: true`, because the decision only knew subscription suspension. A product would have offered a save button the platform refuses. Found by `test_12_sso_per_product.py`. | Fixed: verify consults `organization_status`; a write check on a suspended organization answers `deny/suspended`; a non-readable organization answers `not_entitled`. |

| G-47 | **P1** | **Telemetry could turn requests into 500s.** The metric registry *raised* when a metric passed 500 label combinations, even in production. The HTTP metrics are route × method × status class over 277 routes, so a long-lived worker could legitimately pass that. | G-59 | **P1** | **The WAL archive only grew, and nothing was scheduled.** The archive is copied into a volume on the same host and nothing deletes from it: 1.2 GB after one day of staging. | G-50 | P2 | **Notification sends held a transaction across the SMTP call** (G-30's claim). Found by the final audit. | Fixed in three steps: a committed claim (SENDING, `attempts + 1`, a 120 s lease), then the send **outside any transaction**, then the outcome in its own transaction. | G-53 | P2 | **The RLS-role, ownership and timeout checks never ran at boot.** They were `check --deploy` checks and the `/healthz/startup` probe, while compose health-checked `/healthz/ready`.
